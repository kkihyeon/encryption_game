## 1. 프로젝트 개요

**암호화 대전(Encryption Game)**은 실시간 멀티플레이어 암호화 학습 게임이다. 플레이어들은 차례로 출제자와 해독자 역할을 바꿔가며, 암호화 알고리즘을 적용해 메시지를 암호화하고 다른 플레이어들이 이를 해독하는 방식으로 진행된다. 단순한 게임성과 교육적 목적(암호화 원리 이해)을 결합한 프로젝트이다.

## 4. 아키텍처 분석

### 4-1. 네트워크 모드

게임은 두 가지 네트워크 모드를 지원한다.

```
┌─────────────────────────────────────────────────────────┐
│                    WAN 모드 (인터넷)                      │
│  Player A (Host) ──── PeerJS STUN ──── Player B/C/D     │
│                       (P2P 직결)                          │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                  LAN 모드 (로컬 네트워크)                  │
│  Player A/B/C/D ──── Python WebSocket Server (Host PC)  │
│                        (릴레이 방식)                      │
└─────────────────────────────────────────────────────────┘
```

- **WAN 모드**: PeerJS를 통해 Google STUN 서버로 NAT 통과 후 P2P 연결
- **LAN 모드**: `server.py`가 WebSocket 릴레이로 동작. `WsPeer` 클래스가 PeerJS API와 동일한 인터페이스를 제공하여 상위 코드 변경 없이 두 모드를 처리

### 4-2. Host-Client 구조

```
Host (game.js)
  ├── 게임 상태(gameState) 단독 보유 및 권한 행사
  ├── 매 ~1초 gameState 전체 브로드캐스트 → 모든 Client
  ├── 암호화 검증 (enc_submit)
  ├── 해독 채점 (guess_submit)
  └── 타이머 관리 (nextTurn, 페이즈 전환)

Client (data.js)
  ├── Host 상태 수신 → 로컬 gameState 덮어쓰기
  ├── 타이머 로컬 보간 (sync 지연 보정)
  └── 입력(암호화 제출, 해독 제출)만 Host에게 전송
```

### 4-3. 스크립트 로딩 순서 (의존성 순서)

```
cipher.js → state.js → network.js → canvas.js → render.js
→ lobby.js → data.js → game.js → settings.js → init.js
```

모든 파일이 의존성 순서를 준수하며, 순환 의존 없음이 정적 분석으로 확인됨.

## 5. 게임 플로우

### 5-1. 전체 흐름

```
로비 (Lobby)
  └─ 방 생성/참가, 닉네임 입력, 라운드 수 설정
       ↓ Host가 게임 시작
출제 단계 (Encoding Phase, 90초)
  └─ 현재 출제자: 암호화 방식(1~2개) + 키 선택 → 원문 입력 → 제출
       ↓
해독 단계 (Guessing Phase, 120초)
  └─ 해독자들: 암호화 순서 추측 + 원문 입력 → 제출 (복수 시도 가능)
       ↓
라운드 결과 (Round End, 5초)
  └─ 정답자에게 키값 공개, 점수 갱신, 순위 표시
       ↓
다음 턴 (모든 플레이어가 출제자 역할 순환)
       ↓
게임 오버 (Game Over)
  └─ 최종 순위 표시
```

### 5-2. 점수 체계

| 상황 | 점수 |
|------|------|
| 해독 성공 (기본) | 10점 |
| 시간 보너스 | `+floor(남은시간 × 0.04)` |
| 오답 | 0점 (감점 없음, 음수 없음) |
| 출제자 제출 실패(타임아웃) | -5점 |

## 6. 암호화 알고리즘 (`cipher.js`)

총 4가지 알고리즘을 지원하며, 최대 2개를 순서대로 체이닝할 수 있다.

| ID | 이름 | 키 | 동작 |
|----|------|----|------|
| 0 | 키 순서 (KEY) | 순열 숫자 (예: `312`) | n글자 단위로 키 순서에 따라 위치 재배열 |
| 1 | 애너그램 (ANA) | 단위 크기 (예: `3`) | 단위별 문자를 역순으로 뒤집기 |
| 2 | 카이사르 (CAE) | 시프트 값 (1–25) | 알파벳 n칸 우측 이동 |
| 3 | 스키테일 (SKY) | 레일 수 (2–10) | 격자에 채운 후 열 방향으로 읽기 |

체이닝 예시:
```
원문 "HELLO" 
  → 카이사르(키=3) → "KHOOR"
  → 스키테일(키=2) → "KORO H" (격자 전치)
```

해독 시 플레이어는 적용 순서를 역으로 추측해야 한다.

## 8. 코드 품질 분석

### 8-1. 긍정적 측면

- **모듈 분리**: 관심사별로 10개 JS 파일로 잘 분리되어 있음 (암호화/상태/네트워크/렌더링 각각 독립)
- **의존성 단방향**: 하위 모듈(cipher, state)이 상위 모듈(game, render)을 참조하지 않음
- **추상화 계층**: `WsPeer` 클래스가 PeerJS API를 에뮬레이션하여 LAN/WAN 모드 전환이 상위 코드에 투명함
- **중앙 상태 관리**: `gameState` 단일 객체로 게임 상태를 관리, 클라이언트 동기화가 단순해짐
- **정적 분석 완료**: DOM ID 전수 검증, 스크립트 로딩 순서, 함수 크로스 레퍼런스 모두 이상 없음 확인

### 8-2. 개선 여지

- **CSS 프레임워크 없음**: 반응형 처리를 수동으로 구현해야 하는 구조 (소규모 프로젝트에선 허용 범위)
- **에러 핸들링**: 네트워크 연결 실패 시 사용자 피드백이 일부 코드 경로에서 누락 가능
- **서버 보안**: `server.py`가 인증 없이 모든 로컬 네트워크 클라이언트를 허용함 (LAN 전용이므로 의도된 설계)
- **암호화 다양성**: 현재 4가지 알고리즘 고정 — 플러그인 방식으로 확장 가능성 있음

## 10. 보안 고려사항

- **치팅 방지**: 암호화 검증은 Host(서버) 측에서 수행 — 클라이언트가 위조한 정답 전송 불가
- **네트워크 격리**: LAN 모드는 동일 네트워크 내에서만 접속 가능 (외부 노출 없음)
- **입력 검증**: 암호화 키 값의 유효 범위 제한 (카이사르 1-25, 스키테일 2-10 등)
- **P2P 특성**: WAN 모드는 STUN 통과 후 직접 연결 — 별도 서버에 게임 데이터가 저장되지 않음

## 12. 결론 및 평가

**암호화 대전**은 Python + Vanilla JS 조합으로 프레임워크 의존 없이 완성도 있는 멀티플레이어 게임을 구현한 프로젝트이다.

**강점:**
- 단일 `.exe`로 배포 가능한 독립 실행 구조
- LAN / WAN 이중 네트워크 모드로 다양한 환경 지원
- 모듈화된 코드 구조로 유지보수성 양호
- 교육적 목적(암호화 학습)과 게임성의 균형

**향후 개선 우선순위:**
1. 해독 제출 검증 버그 수정 (이슈 #3 — 게임플레이 직접 영향)
2. 해독자 UI 개선 (선택 방식 수 표시, 색상 버그)
3. 정확한 원문 해독 보너스 점수 시스템 추가
